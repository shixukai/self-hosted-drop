# 自托管 Drop：静态站点发布平台

## 需求规格说明书 v1.1

文档日期：2026-10-14  
文档状态：需求草案，可用于评审和开发拆分  
适用场景：在自有物理机上发布 HTML 技术报告、交互演示和已构建的静态网站  
范围定义：单机、自用为主、受信任发布者、公众只读访问

> 核心目标：登录后台，把 HTML、ZIP 或网站目录拖进去，得到一个可分享的 HTTPS 网址。以后更新同一个项目，网址不变；新版本出错，可以回滚。

本文中的容量、性能和保留期均为建议的首版默认值，不是对现有物理机性能的承诺，也不代表用户已经确认。技术实现建议与必须满足的产品行为分开描述。本版聚焦静态站点发布平台本身，外部访问入口作为既有环境使用。

## 1. 背景、目标与边界

### 1.1 背景

当前主要需求是快速发布 AI 生成的 HTML 报告和演示页面，并持续更新、方便管理。用户希望改用自己的物理机承载站点，面向中国大陆访问者，不再把 Cloudflare Workers、CDN 或 Tunnel 放在必经访问链路中。

本项目只实现“上传即可发布”的产品体验，复用用户已提供的访问入口。开发范围包括站点管理、上传校验、版本发布、预览回滚、自动化 API 和应用运维，不包括外部接入建设。

### 1.2 产品目标

| 编号 | 目标 | 判断标准 |
|---|---|---|
| G-01 | 发布简单 | 首次初始化后，发布者无需 SSH、编辑代理配置或为每个站点创建容器 |
| G-02 | 链接稳定 | 同一站点发布新版本、修改显示名称或执行回滚，正式网址保持不变 |
| G-03 | 页面资源可用 | 管理界面资源随应用部署；发布检查识别缺失本地资源和外部依赖 |
| G-04 | 易于自动化 | 管理界面与 API 使用同一套部署逻辑，可由本地 Agent 或 CI 上传 |
| G-05 | 出错可恢复 | 无半成品上线；失败不覆盖旧版本；支持版本回滚和整机恢复 |
| G-06 | 单机可维护 | Docker Compose 部署，配置可导出，数据可备份，不引入 Kubernetes |

### 1.3 首版不做

不提供服务器端代码执行、在线 npm 构建、Docker 应用托管、PHP/JSP/Node.js 运行环境、数据库托管、边缘函数、Git 自动构建、计费系统或公开注册。支持 Vue/React 等框架的静态构建产物，但不支持依赖服务端渲染的运行服务。

页面中的 JavaScript 可以在访问者浏览器运行；服务器只保存和分发文件。这不代表页面内容天然安全，安全边界见第 7 章。

## 2. 运行环境与应用边界

### 2.1 运行环境

首版部署在用户已有物理机上，按受支持的 Linux、Docker Engine、Docker Compose、本地 SSD 和可持久化数据目录设计。CPU、内存和磁盘参数用于调整容量与并发目标，不预设具体硬件型号。外部访问入口作为既有环境使用，不列入本项目的建设或验收范围。

若物理机还承担其他业务，必须给本平台独立的数据目录、容器网络和资源配额，不覆盖已有代理、数据库或业务端口。

### 2.2 应用就绪检查

| 检查项 | 必须取得的结果 |
|---|---|
| 运行环境 | 应用容器及数据库可启动；数据目录可读写；持久化配置生效 |
| 隔离 | 使用独立数据目录和资源配额，不覆盖其他业务配置 |
| 安全 | 管理后台、数据库、代理管理 API 不因发布站点而暴露 |
| 恢复 | 已完成一次从独立备份恢复的演练 |
| 页面依赖 | 管理界面资源随应用部署；样例站点本地资源可访问，外部依赖有提示 |

## 3. 用户角色与版本范围

### 3.1 角色

| 角色 | 首版权限 |
|---|---|
| 管理员 | 管理站点、部署、系统设置、API Token、备份和审计；首版一个管理员账号 |
| 自动化发布者 | 通过 Token 在获授权项目中读取状态、上传或发布；不自动获得系统管理权限 |
| 普通访客 | 访问已公开站点；不能上传、查看后台、枚举私有部署或调用管理 API |

### 3.2 优先级

P0 是首个可用版本必须完成的范围，包含安全、失败恢复和备份，不等于只做“上传按钮”。P1 在首版稳定后增加。P2 只保留扩展方向，不进入本轮开发承诺。

| 范围 | P0：首版 | P1：下一版 | P2：按实际需求评估 |
|---|---|---|---|
| 发布 | HTML、ZIP、目录；入口识别；完整版本上传 | 粘贴 HTML；断点续传；文件差异上传 | 在线编辑 |
| 版本 | 受控预览；正式发布；更新；回滚；暂停 | 版本差异对比；定时发布 | 多分支环境 |
| 自动化 | 受限 Token、REST API、可运行的上传脚本 | 独立 CLI、MCP、Git 触发上传构建产物 | 隔离的在线构建 |
| 权限 | 单管理员；项目级 Token；预览鉴权 | 多用户、站点级角色；正式站点密码保护 | 企业 SSO |
| 运维 | 健康状态、日志、配额、备份、恢复 | 可用性通知、访问概览、批量导入 | 多节点和 CDN |

正式站点的密码保护不属于 P0。机密页面在该功能实现前只能用于受控预览或独立的内网入口，不能误以为“网址不公开”就是私有。

## 4. 核心流程与页面

### 4.1 首次发布

登录后台 → 拖入 HTML、ZIP 或目录 → 自动识别入口 → 填写显示名称和站点标识 → 查看发布检查结果 → 点击“发布并生成公开链接” → 上传及校验 → 准备不可变版本 → 切换正式版本 → 显示并复制正式网址。

新建站点在成功切换前处于 DRAFT。首次发布按钮必须明确表示内容将公开，不能仅写“保存”。上传结束不等于发布成功；界面须区分上传、处理、就绪、上线各阶段。

### 4.2 更新现有站点

进入站点详情 → 选择“上传新版本” → 新版本通过校验 → 可先预览 → 发布到同一正式网址。旧版本保持可用，直到新版本正式切换。文件名相同不代表原地覆盖。

### 4.3 回滚

在部署历史选择可用版本 → 查看版本说明 → 确认回滚 → 将正式路由切换到该版本 → 验证实际生效结果 → 记录一条新的发布事件。回滚不修改旧文件，也不删除后来版本。

### 4.4 自动化发布

Agent 在自己的环境生成或构建静态文件 → 打包 ZIP → 调用上传 API → 轮询部署结果 → 根据请求模式进入预览或自动申请正式发布 → 返回结构化的部署 ID、正式 URL 和最终状态。

该流程通过普通 HTTP API 实现，不要求绑定特定 AI 厂商。Agent 在哪台机器运行，就必须能从那台机器访问管理 API；API 仅内网可达时，云端 Agent 不应被宣称可以直接发布。

### 4.5 页面清单

| 页面 | 必须展示或操作的内容 |
|---|---|
| 登录与初始化 | 初始管理员设置、登录失败提示、会话退出 |
| 站点列表 | 名称、正式网址、状态、当前版本、最后发布时间、占用空间；搜索和筛选 |
| 新建/上传 | 拖拽区、文件树摘要、入口、名称、slug、资源及外链检查、明确的公开发布操作 |
| 站点详情 | 打开网址、复制链接、上传版本、编辑名称、暂停/恢复、删除 |
| 部署历史 | 阶段、部署说明、时间、操作者、大小、错误、预览和回滚 |
| Token 管理 | 新建、授权范围、到期时间、最后使用时间、撤销；不重复展示原始密钥 |
| 系统状态 | 磁盘及配额、待处理任务、最近备份、应用版本与配置诊断 |

不把上传页面以内联脚本方式直接嵌入管理后台。预览默认在与管理后台不同源的新标签页打开，使用无 opener 的打开方式。

## 5. 功能需求

### 5.1 FR-01 初始化与配置（P0）

首次启动通过一次性初始化凭据创建管理员；初始化成功后入口失效。初始化项包括既有访问地址规则、数据路径、容量限制、历史保留期、时区和备份目标。访问地址仅用于生成站点链接和安全校验；平台只管理自身应用路由，不修改外部接入配置。

提供示例配置及应用自检命令，检查数据库连接、存储读写、剩余空间和内部路由服务。检查结果必须区分“通过”“失败”“无法自动判断”，并提供可执行的修复提示。

### 5.2 FR-02 登录与授权（P0）

所有写操作必须鉴权。管理员密码使用成熟框架的安全密码哈希机制；限制登录尝试，提供会话过期和主动退出。首版通过主机维护命令重置管理员密码，不依赖邮箱服务。

API Token 使用高熵随机值，原文只展示一次，服务端只持久化不可逆摘要。支持项目范围、操作范围和到期时间；撤销后立即禁止新请求。默认不授予删除站点、系统配置和跨项目权限。

### 5.3 FR-03 站点管理（P0）

站点至少包含不可变 ID、显示名称、slug、描述、状态、当前正式部署和创建时间。显示名称支持中文，建议上限 100 个字符；显示名称可以随时修改，不影响正式网址。

slug 仅允许小写字母、数字和连字符，建议 3–40 个字符，不得以连字符开头或结尾；全局唯一。保留 admin、api、www、系统预览前缀 d- 等名称。创建时可由名称生成候选值，冲突时明确提示，不偷偷修改已经选定的地址。

P0 发布后不修改 slug，避免旧链接及浏览器存储的迁移复杂度。P1 的“更换网址”必须与“改显示名称”分开，并明确旧链接处置策略。

### 5.4 FR-04 文件上传（P0）

支持单个 .html/.htm、ZIP 和网站目录；不支持目录选择的浏览器应提示改用 ZIP，不能把平台整体标为不可用。目录上传保留相对结构，采用同一套校验和版本生成逻辑。禁止上传绝对路径，上传文件的路径不得成为宿主机目标路径。

展示上传字节进度、已处理文件数和服务端阶段；支持取消尚未进入正式切换的任务。上传中断时允许重新提交；断点续传不属于 P0。后台页面刷新后，通过部署 ID 恢复查询，不自动重复发布。

### 5.5 FR-05 入口与发布目录识别（P0）

| 输入 | 首版行为 |
|---|---|
| 单个 report.html | 保留原文件；将站点 / 内部映射到它，不强行更改原文件名 |
| 根目录存在 index.html | 默认使用根目录和 index.html |
| ZIP 只有一个外层目录，且其中有 index.html | 建议剥离该层，发布前展示识别结果 |
| dist/ 等目录中存在入口 | 允许选择该发布目录；不假定任意 dist 都一定正确 |
| 有多个可能入口或多个候选根目录 | 要求发布者选择；API 未提供时返回可定位错误 |
| 没有入口、只有源代码 | 拒绝发布，提示上传构建产物；服务器不执行构建 |

支持相对资源地址、根绝对资源地址、嵌套目录、中文文件名和 URL 编码路径。文件路径大小写行为以 Linux 大小写敏感语义为准；发现仅大小写不同的高风险冲突时提示并按校验规则拒绝。

### 5.6 FR-06 发布前检查（P0）

进行本地资源引用检查：至少覆盖 HTML 中的 script、link、img、iframe 静态引用和 CSS url 引用。列出缺失本地资源、明文 HTTP 依赖、外部脚本/字体/图片/API 地址，以及可能的密钥文件。

入口缺失、危险路径、超限、明确的秘密文件阻断发布；普通资源缺失和外部依赖默认警告，发布者可以确认继续。不能把静态扫描宣称为能发现所有动态 import、运行时拼接 URL 或业务错误。

服务器不主动下载外部 URL，也不自动代理外链，以免引入 SSRF、授权和版本变更问题。发布检查须区分本地资源与外部依赖；不将外部服务的可达性作为平台能够保证的能力。

### 5.7 FR-07 部署版本与任务状态（P0）

每次成功接收上传创建唯一 deploymentId，保存产物哈希、发布目录、入口、文件清单、字节数、操作者、说明及时间。所有可发布版本不可变；同名文件在不同部署中互不覆盖。

处理状态：RECEIVING → QUEUED → VALIDATING → EXTRACTING → CHECKING → READY；失败进入 FAILED，可取消阶段进入 CANCELED。目录或单 HTML 输入可跳过不适用的 EXTRACTING 阶段。客户端只在上传校验和完整性检查完成后收到“上传完成”。

“处理成功”和“当前线上版本”是两件事：READY 只表示可供预览或发布；是否线上生效，由发布记录和站点 appliedDeploymentId 表示。失败必须包含稳定错误码、可理解原因和可执行修复提示，不返回服务器敏感路径。

### 5.8 FR-08 正式发布和固定网址（P0）

正式 URL 根据初始化时提供的既有访问地址规则与站点 slug 生成。同一站点的后续发布不改变该地址。新建项目自动建立站点到当前部署目录的内部应用路由；日常发布不要求手工编辑路由配置。

部署必须先在不可公开的暂存区完整准备并校验，再进入不可变发布区，最后切换正式路由。禁止边上传边让访客读取，禁止把新文件逐个复制到当前线上目录。

“发布成功”必须在内部路由实际切换并完成受控的内容读取检查后返回。未完成时显示 PENDING/APPLYING，不得提前写“已上线”。路由应用失败时保留 READY 产物及原正式版本，不得返回成功。

### 5.9 FR-09 预览（P0）

按既有访问地址规则为每个部署生成独立预览地址，始终绑定该 deploymentId，不随正式版本切换。预览使用与管理后台不同的浏览器源；每个部署的资源及凭据必须隔离。只有持有效、可撤销、绑定 deploymentId 的凭据才能访问；随机难猜网址本身不是鉴权。

预览访问链接默认有效 1 小时。首次凭据交换后使用该预览主机专用的 HttpOnly、Secure Cookie，并跳转移除地址中的临时凭据。临时凭据不得写入访问日志；预览响应使用 no-store、no-referrer 和禁止索引策略。所有 HTML、资源文件及 Range 请求都必须经过鉴权，不能只保护首页。

预览鉴权服务不可用时拒绝访问，不降级成公开。部署产物仍保留时可重新创建预览凭据；预览链接到期不等于删除部署。

### 5.10 FR-10 回滚、暂停与删除（P0）

回滚只能选择同一站点已校验且文件完整的版本，走与正式发布相同的切换过程。无法切换时保留当前版本并明确报错。

暂停站点后，正式主机名拒绝所有页面和资源请求；返回统一的不可用页面，建议状态码 503。P0 将暂停同时用于紧急下线，应一并撤销该站点现有预览凭据。恢复后才允许生成新凭据。

删除采用二次确认，立即撤销正式路由和全部预览访问，进入 7 天回收期；回收期内可恢复，但恢复默认保持暂停。到期或管理员明确永久删除后，异步回收无引用产物。删除/暂停不能撤回访客已经下载或缓存的公开内容。

### 5.11 FR-11 静态文件与路由（P0）

支持常用 HTML、CSS、JavaScript、JSON、图片、字体、SVG、WASM、PDF 和必要的音视频资源。具体扩展名采用管理员可审计的允许清单；不执行任何服务器模板、脚本或上传配置。JS/SVG 是浏览器可执行内容，必须遵守第 7 章隔离要求。

支持 GET、HEAD、正确 Content-Type、压缩、ETag 和必要的 Range 请求。关闭目录列表；未绑定主机名返回统一错误，不能落到管理后台或默认文件目录。敏感目录即使被意外写入也不得通过公开路由获取。

站点提供 static 与 spa 两种模式，默认 static。SPA 回退只用于预期的 HTML 导航；缺失的 JS/CSS/图片、平台保留路径和明确的资源请求必须返回 404，不能一律返回 index.html。

### 5.12 FR-12 缓存及版本边界（P0）

正式地址上的 HTML 和非内容寻址资源默认使用 no-cache 并正确生成校验标识；不把“no-cache”解释为禁止存储，它要求复用前验证。部署变化后同名文件的校验标识必须反映内容变化。鉴权响应使用 private, no-store。[S5]

P0 不默认给全部资源设置长时间 immutable。只有明确使用内容哈希寻址且遵循内容不可变约束的资源，才可启用长缓存策略。服务端不能强制关闭已打开的旧页面，也不承诺替用户清理 Service Worker 缓存。

原子路由切换只保证单次请求不会读到半写文件，不保证页面的多次请求跨切换时都属于同一版本。重要项目应使用构建产物的内容哈希资源；需要固定版本展示时使用绑定部署的受控预览。此限制必须出现在开发文档和验收记录中。

### 5.13 FR-13 日志、存储和备份（P0）

记录发布、回滚、暂停、删除、配置变更和 Token 操作的审计日志；访问日志与管理审计分开，支持按站点、部署和 requestId 定位。屏蔽 Authorization、Cookie、密码和预览凭据，不把完整查询字符串默认落盘。

统计当前版本、历史版本、暂存文件、回收站和预留中的容量。清理前先输出计划；不得删除当前版本、被固定保留版本、正在发布版本及仍被引用的文件。失败上传和过期暂存按规则回收。

提供备份及恢复命令，覆盖数据库、不可变产物、内部路由清单和应用配置。备份应写到独立设备或独立备份目标，不把同一物理磁盘上的另一个目录当作灾难恢复能力。凭据备份须加密，密钥独立保管。

备份先取得一致的数据库快照和被引用产物清单，备份期间固定保留这些产物，避免并发回收删除；复制后逐项验证哈希并生成备份完成标记。恢复时必须验证清单完整性并重建实际路由，不直接把半完成备份标记为可恢复。

以下数值是本项目的起始配置和验收目标，可在拿到硬件及网络参数后调整。服务端配置为最终约束，浏览器限制仅用于提前提示。容量单位 MiB/GiB 使用二进制计量。

| 项目 | 首版默认值/目标 | 说明 |
|---|---|---|
| 站点数 | 100 个 | 可配置上限，不按每站点常驻容器计费或分配进程 |
| 上传包 | 200 MiB | HTML、ZIP 或目录合计入站大小 |
| 解压后总量 | 1 GiB/部署 | 流式累计实际写入字节，不信任 ZIP 元数据 |
| 单文件 | 100 MiB | 明确限制，超限给出对应文件名 |
| 文件数/层级 | 10,000 个 / 20 层 | 建议相对路径不超过 512 UTF-8 字节 |
| 全局可管理产物 | 20 GiB | 包含历史版本、回收站、暂存和配额预留；可按磁盘调整 |
| 低磁盘保护 | 保留至少 5 GiB 且不少于卷容量 10% | 使用两者较大值作为保留空间，避免挤满主机 |
| 部署处理并发 | 全局 2 个 | 单站点正式发布串行；队列有上限并返回明确忙碌状态 |
| 历史保留 | 每站点最近 10 个 READY 版本 | 当前和固定保留版本不自动删除；超过配额时拒绝新增而非偷偷删保护版本 |

| 普通包处理 | 20 MiB、≤500 文件，上传完成后 P95 ≤15 秒 | 从完整接收上传内容开始计时，不含客户端上传时间 |

## 7. 安全需求与威胁边界

### 7.1 SEC-01 安全上传与解压

ZIP 可能导致越界写入、资源耗尽和恶意内容传播，不能把“能解压”当作校验通过。上传大小限制还必须作用于解压后的实际内容。[S1]

实现必须拒绝绝对路径、.. 逃逸、混合分隔符绕过、NUL、非法路径、重复规范化路径、符号链接、硬链接、设备文件、加密 ZIP 和不支持的压缩格式。不递归展开嵌套压缩包。相同规则适用于目录上传，而不是只检查 ZIP。

在独立暂存目录中流式写入，执行文件数、实际解压字节、单文件和处理超时限制；检测疑似压缩炸弹。校验结束再转入发布区。不得调用 shell 拼接用户路径进行解压。释放配额、清理临时文件及失败记录必须可重复执行。

拦截 .env、.git、SSH 私钥、证书私钥等明确敏感文件；忽略 .DS_Store、__MACOSX 等无业务元数据并报告。其他秘密扫描只作为辅助，不承诺识别所有 Token。

### 7.2 SEC-02 浏览器与管理面隔离

浏览器按协议、主机和端口区分源；把不同站点放在同一主机名的不同路径下，不会形成独立源。管理后台、各内容站点及部署预览采用既有地址规则提供的独立浏览器源；不得把路径隔离当作浏览器安全隔离。[S2]

后台仅通过既有管理入口提供。管理 Cookie 使用 Secure、HttpOnly、SameSite、Path=/ 且不设置 Domain，优先采用 __Host- 前缀。管理写接口校验 Origin/CSRF；不向内容站点开放带凭据的通配 CORS。不能仅依靠 SameSite 防范同站不同源请求。[S3]

上传的 HTML 不经过删除所有脚本的“净化”，以保留交互功能；因此必须视其为可执行的不可信浏览器内容。预览不能与后台同源；管理后台不得读取并执行站点脚本；上传标题和错误信息必须转义。

平台不保证上传页面对访客无恶意，也不能靠容器限制已在访客浏览器运行的脚本。首版仅允许受信任发布者使用，禁止公开匿名上传。

### 7.3 SEC-03 文件系统与进程权限

公开服务只挂载已验证的发布区，不能读取暂存、数据库、备份、宿主机 HOME 或 Docker Socket。上传工作进程仅能写入专用目录，使用受限身份和 CPU、内存、磁盘约束。内容区不接入 PHP/FastCGI 等执行器。

文件服务的 root 设置不能替代操作系统隔离；Caddy 文档明确指出，root 本身不提供沙箱保证，符号链接仍可能访问目录外的内容。[S4] 因此必须同时拒绝上传链接、校验实际路径、限制挂载和权限。

### 7.4 SEC-04 内部接口与路由权限

Caddy 管理 API 只绑定本地 Unix Socket 或专用内部接口；仅发布服务可调用。数据库不暴露公网。只信任实际代理来源的转发头，不接受用户伪造 X-Forwarded-For、Host 或内部鉴权结果。

Host 只匹配已经登记的站点或预览主机名，不直接拼成文件系统路径。对所有请求执行统一路径规范化，保留 /_drop/ 给平台预览鉴权，拒绝上传占用。平台只能更新自身站点路由，不能改写其他业务的配置。

### 7.5 SEC-05 滥用、限流与内容处置

限制登录、API、上传并发、失败次数及公开流量；达到上限返回明确的 429/配额错误，不拖垮其他服务。支持管理员紧急暂停整个站点并撤销预览。

公开内容默认发送 noindex，但这不是访问控制，也不保证搜索引擎遵守。内容是否合法和是否适合公开由发布者负责确认。日志保留期限应根据实际合规适用性确定并可配置，不把某个固定天数宣称为普遍合规答案。

## 8. 架构建议与复用边界

### 8.1 推荐首版拓扑

公众浏览器 → 既有访问入口 → 内部 Caddy 静态文件服务 → 只读的不可变站点产物。

管理员或 Agent → 既有管理入口 → Drop 服务（后台、API、后台任务、预览鉴权、路由协调）→ PostgreSQL 与专用数据目录。

Drop 服务通过受保护的本地管理接口更新内部 Caddy 路由。Caddy 仅承担本平台的静态文件分发与版本切换，不接管既有外部入口或其他业务配置。公开正式站点读取文件不经过管理 API 或数据库；预览请求单独走鉴权，鉴权失败时关闭访问。

首版用一个代码仓库、一个业务服务和一个受限后台工作单元即可，工作单元可在同容器内作为独立低权限进程运行。不为每个静态站点创建容器。不需要微服务、Redis、消息中间件、对象存储或 Kubernetes。

### 8.2 技术选型原则

| 部分 | 建议 | 必须满足的行为 |
|---|---|---|
| 内部路由及文件服务 | Caddy | 站点到部署目录的映射、静态分发、热更新、持久化配置 |
| 后台界面 | 团队熟悉的前端框架 | 本地打包静态资源，运行时不依赖海外脚本/字体 CDN |
| 业务服务 | 优先使用团队熟悉的后端栈 | 流式上传、任务恢复、权限、版本和路由协调 |
| 元数据 | PostgreSQL 单实例 | 发布记录、任务持久化、幂等、并发控制和审计 |
| 产物 | 本地文件系统 | 暂存/发布分区、不可变版本、校验和、可迁移 |
| 部署 | Docker Compose | 一键启动、健康检查、持久化目录和资源限制 |

业务服务技术栈暂不锁定具体语言或框架版本。版本应在实施时按支持周期和依赖兼容性锁定，交付镜像使用确定版本或摘要，不使用浮动 latest。

### 8.3 哪些要开发，哪些不必开发

| 需要开发 | 直接复用成熟组件 |
|---|---|
| 站点管理、上传体验、入口识别、预览权限 | HTTP 静态文件服务组件 |
| 安全解包编排、不可变部署、文件清单 | 安全维护的 ZIP 库、密码哈希库 |
| 正式路由切换、回滚、失败恢复、并发规则 | Caddy 静态服务、路由热加载 |
| API、Token、幂等、审计、配额 | Web 框架、数据库驱动、迁移工具 |
| 备份编排、恢复验证、状态展示 | 数据库备份工具、容器运行时 |

Caddy 已提供配置热加载和失败时恢复旧配置的能力，可以复用；但数据库、路由状态和文件的一致性仍须由本项目实现，不能把网关热更新等同于整条发布链路的事务。[S6]

## 9. 数据与一致性规则

### 9.1 核心对象

| 对象 | 关键字段 |
|---|---|
| Site | id、name、slug、status、entryPath、routingMode、desiredDeploymentId、appliedDeploymentId、generation |
| Deployment | id、siteId、status、artifactHash、manifestPath、rootPath、fileCount、expandedBytes、createdBy、errorCode |
| Publication | id、siteId、deploymentId、expectedGeneration、targetGeneration、status、action、appliedAt |
| SiteRoute | routeKey、siteId、deploymentId、kind、generation、appliedAt；只记录正式/预览地址与部署的内部映射 |
| ApiToken | id、digest、scopes、siteIds、expiresAt、revokedAt、lastUsedAt |
| PreviewGrant | id、deploymentId、tokenDigest、expiresAt、revokedAt；会话只授权相应部署 |
| AuditEvent | id、actor、action、siteId、deploymentId、requestId、result、timestamp |

文件清单每项记录规范化相对路径、大小、内容哈希和媒体类型。文件内容不塞进数据库。后台所有时间存 UTC，界面按配置时区显示，日志和 API 使用带时区的标准时间格式。

### 9.2 磁盘布局约束

建议将 uploads、releases、runtime、backups 分开。只有 releases 中明确就绪的部署可以被公开网关读取；backups 默认在独立目标中，示意名称不表示应该与发布区同盘。

部署路径使用服务端生成的 ID，不使用用户输入的站点名拼接。暂存与发布区应位于支持预期原子移动语义的同一文件系统；跨盘复制必须先复制并校验到目标暂存区，再做最终切换。

### 9.3 幂等与并发

上传和发布接口接受 Idempotency-Key，按 Token 身份、项目和操作范围隔离。同键同内容返回原操作；同键不同内容返回 409。完整载荷摘要确认前不得把半截上传认定为可复用成功任务。幂等记录建议至少保留 24 小时。

每次正式切换带 expectedGeneration，使用比较并交换规则；两个发布基于同一 generation 竞争时只允许一个成功，另一个保留 READY 并返回发布冲突。禁止“较早提交、较晚完成”的慢任务静默覆盖已经上线的新版本。

单站点发布串行，网关整份配置更新还需要全局协调，避免不同站点同时发布时互相覆盖路由。

### 9.4 崩溃恢复与真实生效状态

发布采用持久化意图和可恢复步骤：产物 READY → 记录发布意图 → 生成并校验带 generation 的路由配置 → 网关应用 → 验证实际配置及入口 → 更新 applied 状态。

数据库、磁盘和网关不是单一事务。服务重启后必须对照持久化发布意图、产物清单和网关当前 generation 恢复状态：已生效但未回写的补记；未生效的重试或失败；无法确认时显示 RECOVERING，并阻止同站点新的切换。不得凭数据库里的“成功”标志假设路由已上线。

后台/数据库短时不可用时，已经公开的静态站点继续由网关最后可用配置服务。新发布和受控预览可以不可用，但不能 fail-open。内部网关有效配置及发布数据持久化，整机重启后无需重新上传。

## 10. API 合约草案

所有管理 API 位于既有管理入口下的 `/api/v1`，使用现有安全访问通道。下面定义资源和行为，最终 OpenAPI 文档需给出请求/响应 schema、鉴权范围、大小限制和全部错误码。

| 方法与路径 | 用途 | 关键行为 |
|---|---|---|
| POST /sites | 创建站点 | 返回 siteId、slug、正式 URL 和 generation |
| GET /sites | 查询站点 | 分页、名称/slug 搜索、状态筛选 |
| GET /sites/{siteId} | 查询站点详情 | 同时返回期望版本和实际生效版本 |
| PATCH /sites/{siteId} | 修改显示信息和配置 | 校验授权；P0 不开放已发布 slug 修改 |
| POST /sites/{siteId}/deployments | 上传 HTML 或 ZIP | multipart；202 返回 deploymentId；目录先按保留路径的 ZIP 契约提交 |
| GET /deployments/{deploymentId} | 查询处理结果 | 状态、进度、警告、错误；不能越权读取其他项目 |
| POST /deployments/{deploymentId}/preview-grants | 创建预览凭据 | 仅 READY；返回一次性入口链接和到期时间 |
| POST /sites/{siteId}/publications | 发布或回滚 | deploymentId、expectedGeneration、action；202 返回 publicationId |
| GET /publications/{publicationId} | 查询实际生效结果 | PENDING/APPLYING/APPLIED/FAILED/CONFLICT/RECOVERING |
| POST /sites/{siteId}/pause | 暂停并撤销预览 | 路由实际生效后才报告完成 |
| POST /sites/{siteId}/resume | 恢复正式服务 | 不自动恢复旧预览凭据 |
| DELETE /sites/{siteId} | 进入回收站 | 需独立 delete scope；默认发布 Token 无权调用 |

上传元数据包含 rootDirectory、entryPath、routingMode、message，以及可选的 publishAfterReady。publishAfterReady 默认为 false；为 true 时必须同时提交 expectedGeneration，并最终通过同一发布规则处理，不创建第二套“快捷但不安全”的逻辑。

错误响应统一包含 code、message、requestId、retryable 和安全的 details。至少区分 AUTH_REQUIRED、FORBIDDEN、INVALID_ARCHIVE、UNSAFE_PATH、ENTRY_NOT_FOUND、SOURCE_NOT_BUILT、QUOTA_EXCEEDED、STORAGE_LOW、DEPLOYMENT_CONFLICT、ROUTE_CONFLICT、ROUTE_APPLY_FAILED。

自动化脚本必须支持非零退出码、明确超时和 JSON 输出。Token 从环境变量或权限受限配置读取，不写入站点内容、生成 HTML、日志或 URL。交付至少一个可运行脚本；下列仅是目标调用体验，不表示已有 CLI：

`drop deploy ./dist --site simpl-report --publish --message "更新分析报告" --json`

## 11. 非功能需求

### 11.1 可用性与兼容性

浏览器前台支持当前稳定版 Chrome、Edge、Firefox 和 Safari；验收时记录具体版本。核心流程可键盘操作，上传和失败状态不只靠颜色表达。公众静态页面的自身浏览器兼容性由页面作者负责，平台验收覆盖代表性样例。

管理端所有脚本、样式和字体随应用部署。内容检测只提示页面外部依赖；不承诺把引用海外服务的网页自动转为离线可用。

### 11.2 可维护性与可观测性

提供健康检查、就绪检查、队列长度、磁盘剩余量、失败发布计数、最近成功备份和内部路由状态。检查接口不公开密钥和内部路径。日志结构化并可关联 requestId、deploymentId、publicationId。

安装、升级、回退和恢复过程有文档及可执行命令。升级前备份，数据库迁移失败不得继续启动写操作；不承诺所有跨版本数据库变更都可逆，应给出对应恢复路径。

### 11.3 数据所有权与可迁移性

产物、元数据及配置保存在自有设备。支持导出单站点的当前版本、指定版本和站点元数据，也能迁移整个平台。公开站点不依赖本平台的专有运行时；导出的文件应能交给普通静态文件服务器使用。

## 12. 验收用例与质量门禁

P0 交付必须提供可重复的测试样例、自动化测试结果和部署记录；不能只用一次人工演示作为全部验收。以下为最小验收集。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC-01 | 上传单个 report.html | / 可访问；原文件名仍可用；返回正确媒体类型和正式 HTTPS URL |
| AC-02 | ZIP 有单层包装目录 | 正确提示发布根目录；CSS、JS、中文图片资源可访问 |
| AC-03 | 目录上传与 ZIP 等价 | 同一目录得到一致的文件清单和页面效果 |
| AC-04 | 缺入口或上传源码 | 阻断并说明原因；不偷偷运行 npm 或构建命令 |
| AC-05 | 同网址更新 v1→v2 | 正式 URL 不变；显示名称修改不影响网址；已确认的请求读完整文件 |
| AC-06 | 上传失败或磁盘不足 | v1 持续可用；v2 不上线；配额及暂存最终被回收 |
| AC-07 | 回滚到 v1 | URL 不变；实际返回 v1；保留回滚审计和 v2 记录 |
| AC-08 | 两次并发发布 | 只有合法 generation 获胜；慢任务不能静默覆盖；冲突可重试 |
| AC-09 | 重复 API 请求 | 同幂等键同内容只创建一次操作；异内容返回 409 |
| AC-10 | 预览未授权/过期/撤销 | HTML、图片、JS 和 Range 均不可获取；无公开兜底路径 |
| AC-11 | 暂停、删除和恢复 | 正式与预览均受控；删除不暴露历史目录；恢复默认暂停 |
| AC-12 | 路径穿越/链接/炸弹包 | 被拒绝；不能写出暂存区、读宿主文件或耗尽磁盘/内存 |
| AC-13 | 管理面跨源攻击 | 内容页面拿不到管理 Cookie；管理写操作不能靠跨源请求完成 |
| AC-14 | SPA 和缺失资源 | 页面路由按设定回退；不存在的 JS/CSS 返回 404 而非 HTML |
| AC-15 | 缓存更新 | 相同文件名内容变化后校验标识变化；页面刷新可取得新内容 |
| AC-16 | 崩溃发生于切换前/后 | 重启能恢复真实生效状态；不出现永久“发布中”或错误成功 |
| AC-17 | API/数据库停止 | 已公开静态站点继续服务；预览鉴权关闭访问；新发布明确失败 |
| AC-18 | 整机重启 | 路由、文件、应用配置和账户保留，不需重新上传 |
| AC-19 | 备份恢复 | 在干净环境恢复并核对版本、内容哈希和路由，记录 RPO/RTO |
| AC-20 | 容量与性能实测 | 完成第 6 章处理耗时、切换耗时及静态服务负载测试，记录硬件配置、结果与限制 |

额外安全检查应覆盖大小写/URL 编码绕过、重复文件名、鉴权资源路径、Host 注入、越权路由变更、上传的 .env/.git、Caddy 管理接口和数据库公网暴露。

## 13. 开发拆分与交付物

### 13.1 建议开发顺序

| 阶段 | 开发内容 | 退出条件 |
|---|---|---|
| M0：应用骨架 | Compose、数据库迁移、应用配置、独立数据目录、内部文件服务及最小权限 | 应用可启动；内部服务及数据持久化检查通过，不影响既有业务 |
| M1：安全发布闭环 | 登录、站点、上传、入口识别、安全校验、不可变版本、路由发布 | 单文件和多文件项目可用，恶意输入与失败不破坏旧站 |
| M2：日常使用 | 完整界面、固定 URL 更新、受控预览、回滚、暂停、删除 | 核心人工流程和版本相关验收通过 |
| M3：自动化与恢复 | API、Token、幂等、并发、崩溃恢复、备份、日志、配额 | API 与界面行为一致，安全/恢复/负载门禁全部通过 |
| P1：体验扩展 | 多用户、CLI/MCP、正式站点密码保护、版本差异对比等 | 按新增需求另行验收，不拖入 P0 |

这些是依赖顺序，不是工期承诺。安全约束从 M0/M1 落地，不能等到全部功能完成后补。

### 13.2 开发工作包

前端工作包：站点列表、上传与入口选择、发布进度、详情和历史、Token 管理、系统状态。

后端工作包：鉴权与项目模型、流式上传和校验、任务状态、配额预留、预览凭据、发布协调、版本回收、API 与审计。

应用运维工作包：Compose、内部 Caddy 路由生成与热加载、进程与存储隔离、备份恢复、健康检查及版本升级。

测试工作包：功能集成、浏览器兼容、恶意压缩包、跨源鉴权、并发幂等、故障注入、恢复演练和应用性能压测。

### 13.3 必交付产物

交付源代码及依赖锁定、可运行镜像与 Compose、配置示例和初始化命令、数据库迁移、OpenAPI、自动上传脚本、测试样例与报告、备份恢复脚本、部署及故障排查手册。

应附一份“已实现/未实现/已知限制”清单，明确无服务端执行、单机单点、页面外部依赖和跨版本多请求一致性边界。不得把尚未完成的 CLI/MCP、正式站点密码保护等功能宣称为已交付。
