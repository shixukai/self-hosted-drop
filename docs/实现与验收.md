| 路径 | 职责 |
|---|---|

| `cmd/drop-worker` | 独立文件检查服务和一次性处理子进程 |
| `internal/app` | 登录、站点、部署、发布、预览、Token、任务、配额、回收和备份 |
| `internal/archive` | 静态产物的安全解包、入口识别、依赖检查和校验 |
| `internal/gateway` | Caddy JSON 路由、候选探测配置、ETag/If-Match 读写 |
| `db/migrations` | 带版本记录和事务的嵌入式 SQL 迁移 |
| `web/src/pages` | 按路由懒加载的实际业务页面 |
| `web/src/api.ts` | API 访问、真实上传进度、错误模型和状态查询 |
| `web/src/zip.worker.ts` | 目录流式压缩及取消 |
| `web/src/upload-files.ts` / `upload-draft.ts` | 原生目录递归读取、输入校验与首页到上传页的一次性内存交接 |
| `api/openapi.json` | OpenAPI 3.1 合约；`scripts/generate-openapi.py` 生成 |
| `scripts` | 初始化、原生开发、自动上传、恢复与契约生成 |
| `tests/integration.py` | 对真实 PostgreSQL/worker/Caddy 的本地验收 |
| `web/tests/browser.mjs` | 独立浏览器端到端操作 |

后端采用 Go 1.27、chi、pgx；当前数据访问为显式 SQL，尚未引入设计建议中的 sqlc 代码生成。前端类型集中定义，OpenAPI 尚未自动生成客户端类型。后续应增加合约生成与兼容性门禁，避免双份类型漂移。

管理 API 使用 `/api/v1`。浏览器写请求使用会话 Cookie + `X-CSRF-Token`，并保留浏览器 Origin；自动化使用 Bearer Token。所有后台 JSON 响应使用 `Cache-Control: no-store`。

列表采用绑定查询条件的不透明游标；站点、部署、文件、发布和审计支持分页。Token 返回全部元数据，备份列表返回最近 100 条。幂等记录保留 7 天；支持上传、入口选择与发布/站点路由操作。同一 key 对应不同请求返回 409，终态重放仍返回原资源。上传只有在完整接收并提交排队事务后建立幂等记录；未提交的 RECEIVING 中断不占住该 key。CLI 的 `--retry-failed` 仅在观察到 FAILED/CANCELED 后以新键尝试一次，不能与显式 `--idempotency-key` 同用；未知结果、处理中或发布失败不触发新上传尝试，错误结果返回已知的 key 与资源标识供后续核对。

## 3. 关键行为

### 3.1 发布与缓存

上传被接受后返回 Deployment；检查成功进入 READY。公开发布另行返回 Publication，客户端等待 APPLIED。上传、检查、数据库接受意图或网关接收配置均不能单独代表发布成功。

已应用或期望暂停状态拒绝发布/回滚，自动发布通过相同状态检查；公开服务恢复要求 `sites:manage` 身份显式操作。自动发布结果保存在 `autoPublicationId` 或独立错误字段；代次冲突、Token 撤销/权限不足、暂停和未确认警告不改变已检查文件的 READY 状态。数据库/结果保存的暂时错误保持重试，接受已提交时通过自动幂等记录关联原 Publication。

升级迁移只关联有可靠自动幂等记录的历史发布；旧版 READY 自动发布请求的处理任务已结束但结果无法确认时，记录 `AUTO_PUBLISH_OUTCOME_UNKNOWN` 并保持 READY，不触发新的自动发布。历史结果未必可重建，须由操作者核对已有发布和正式响应后再决定显式发布。

恢复操作可显式选择同站点的 READY/AVAILABLE 版本，校验报告哈希与警告确认，覆盖无旧正式版本的暂停/恢复草稿和旧产物不可用的站点；未指定版本时继续要求旧正式版本可用。替代版本恢复也生成 Publication 并等待 APPLIED，不通过普通发布权限隐式恢复。

新版本先经内部内容端口验证，再切换正式路由。协调器串行管理专用 Caddy，单站点 generation 防止并发覆盖。网关结果不明时记录 RECOVERING，阻止其他切换/回收/备份覆盖未确认状态；后续任务重试读取实际配置。

普通自动恢复在提交 APPLIED 前验证完整目标配置、全部活跃产物和每个站点的正文/ETag 或禁用响应，并再次回读配置；补偿也须验证完整已应用基线的文件与内容后才记录 FAILED。单个目标路由正常不能掩盖其他站点的配置、正文或资源漂移。

全局阻断保护的是完整配置快照的补偿安全。维护命令 `drop reconcile <publication-id>` 默认只读检查，返回配置哈希、待处理 Publication 和期望/已应用漂移；写入模式要求 `--expected-config-hash`。`complete` 只确认已观测到的完整目标配置并验证产物、正文、ETag，补偿已被要求时拒绝该模式；`restore-applied` 从数据库已应用状态重建基线，通过 If-Match、完整回读与逐站点响应核验后才确认失败并结束目标任务。核验失败保持 RECOVERING，其他待处理发布保持原状。运行步骤见[运行与部署 4.2 节](运行与部署.md#42-未知发布状态的核验与恢复)。

运维写入选择持久化为 `operatorMode`，未核实完成时后台任务保持阻断；重新 inspect 并以新哈希确认后允许 complete 退回 restore-applied，已选择的 restore-applied 不能反向改为 complete。完整验证提交后才清除该选择。inspect 提供目标操作/状态/代次/版本以及目标/已应用完整配置匹配布尔值，不验证文件与公开正文，其 `verifiedSites` 为 0。

`doctor` 对待处理发布意图和期望/已应用状态或版本差异输出 JSON 并返回非零退出码；确认失败后 generation 的单独推进不属于状态漂移。

正式页面设置 no-cache，浏览器以内容 SHA-256 ETag 重新验证。移除 Last-Modified 并剥离对应日期条件头，避免同秒同大小更新产生错误的 304。SPA 只对接受 HTML 且路径无扩展名的缺失路径回退，缺失 JS/CSS/图片不会返回首页。

### 3.2 输入和隔离

首页站点区域与上传页均接收 HTML、ZIP 和已构建的网站目录。首页读取目录时显示文件数量并支持取消；读取成功后保留文件和相对路径进入上传页，自动建议名称与站点标识。拖放只准备选择，上传检查与公开发布仍由用户分别确认。站点详情的正式版本面板提供访问入口与复制图标，复制固定公开链接并显示操作结果。

文件对象保存在短期内存中，路由状态只携带一次性标识；不写入 URL 或浏览器持久存储。返回首页后普通新建不会重放已消费的选择，刷新页面后需重新添加文件。空目录、不支持的独立文件与超限输入显示错误；目录递归读取持续处理浏览器返回的所有批次。

ZIP 条目拒绝绝对路径、上级目录、反斜杠、控制字符、敏感配置、链接/特殊文件、大小写和 Unicode 冲突、保留路径；使用 `os.Root` 约束落盘。限制基于实际读取字节，不依赖归档声明。

静态依赖扫描不发起网络请求。它检查 HTML/CSS 常见引用与 JS 外链字面量；无法穷尽动态 JavaScript 依赖，也不下载外部资源。外链、混合内容、缺失资源或扫描上限会显示警告。管理员手动确认或显式 `warningsPolicy=allow` 才允许带警告发布。

封面使用本地装饰图案；没有自动执行用户 HTML 生成缩略图。正式公开页面本身仍允许静态网站的 JS 在访问者浏览器中运行。

### 3.3 维护和数据

导出 ZIP 将站点文件放在 `content/`，元数据置于 `drop-export.json`，避免上传文件与平台元数据重名。重新导入此 ZIP 时，根目录选择 `content`。

导出请求使用临时 pin 保护文件，在请求返回时释放；30 分钟到期仅作为异常中断或清理失败的兜底。终态上传至少稳定 150 秒且无活跃 PROCESS 任务后，在 GC/配额锁与行状态复核下按上传、quarantine 和未可用 release 的完整残留量缩减预留；逻辑大小、已分配块和元数据余量均计入，扫描不确定时保留原值。原始上传在 24 小时后按安全条件清理，其他残留仍计入预留。

备份 GC 锁会延后旧正式版本回收与终态残留的预留刷新；原始上传暂存期清理不使用该锁，删除后仍须完整计量通过才释放相应预留。

备份使用数据库导出快照匹配不可变产物集合，Restic 加密保存。恢复脚本只接受新目录和空库；运行中的入口切换保留为明确的运维步骤。临时上传不属于恢复目标。

## 5. 生产验收待办

- **目标设施：** `douyacn.com` 的 DNS/证书/Host 转发、既有站点 Cookie、实际 Linux 资源与磁盘配额、入口上传与超时设置。

- **公开限流：** 当前官方 Caddy 镜像不含额外限流模块；接入现有入口限流后再做验收。
- **故障注入：** 各落盘/数据库提交/网关应用点的 SIGKILL、网关响应丢失、租约失效、数据库连接断开和 GC/导出/备份竞态需扩大自动化覆盖；reconcile 在真实故障、外部配置修改及多站点队列下的生产恢复演练仍需验收。
- **备份设施：** 独立异机仓库与解密材料保管，生产快照恢复和真实 RTO/RPO；本机演练无法代替异机灾备。
- **运维能力：** Prometheus 指标、内置定时备份、上传失败逐项恢复 UI 尚未实现。日志、状态 API 和维护命令为本版观测入口。
- **协作与策略：** 单实例管理服务；保留策略缩短只预留设计，当前 API 限制为延长。完整 P0 不能仅凭功能列表判定完成。
